# pnpm 11.28

Compared with pnpm 11.27.x. Patch changes within 11.28.x are listed at their exact release boundaries.

## 11.28.0

`forceIgnoresPlatform` becomes available; only explicit values move. pnpm v11
and v12 have different defaults, which the migrator does not materialize.
Dynamic `userAgent` values containing environment placeholders remain in their
sources because pnpm ignores them in project configuration.

## 11.28.1–11.28.6

From 11.28.1, invalid `patchedDependencies` maps and non-array `packages` values
are retained with diagnostics. Incompatible existing workspaces fail validation
before writes.

From 11.28.3, non-null `allowBuilds` values must be maps of booleans or strings.
From 11.28.4, non-null `allowUnusedPatches` must be boolean, and non-null
`ignoredOptionalDependencies` / `requiredScripts` must be string arrays.
From 11.28.5, `httpProxy` and `httpsProxy` must be strings, including when empty;
null is incompatible in 11.28.5. From 11.28.6, null is accepted again and leaves
the proxy unset. Invalid values remain in their sources with diagnostics.

## 11.28.7

`maxTarballUnpackedSize` accepts a nonnegative safe integer in bytes or null.
Numeric `.npmrc` values become YAML numbers. The migrator does not add pnpm's
4 GiB default. `autoInstallPeersFromHighestMatch` accepts boolean or null;
`externalDependencies` accepts a string array or null.

## 11.28.9

From pnpm 11.28.9, v11 registry declarations also accept `serverType: pnpr`.
Earlier or unconfirmed v11 targets retain the complete registry map. The setting
does not enable v12-only registry fields such as `networkConcurrency` or `ecosystem`.

## Other recorded patches

11.28.2 and 11.28.8 add no field migration rule in the corresponding audits.
11.28.10 and 11.28.11 leave the ordinary workspace schema unchanged. The latter
normalizes default-registry prefix lockfile keys; source settings need no rewrite.

## 11.28.12

Compared exact tags **11.28.11 → 11.28.12**. The workspace field types stay
unchanged. Registry URLs containing environment placeholders now fail native
configuration reading instead of being ignored, for workspace YAML and project
`.npmrc`. Dynamic proxy, `pnprServer` and `userAgent` workspace values now produce
warnings when ignored. Existing migrator protections already preserve these
incoming values and reject unsafe existing workspace settings before writes.
No new field capability or conversion is needed.

`projectScopedOptionalPeers` is identified in unknown-setting warnings as a
newer v12 setting; this does not add v11 support. Optional-peer scoping fixes
under `dedupePeerDependents: false` do not introduce that v12 field. Registry
server types for config dependencies, catalog/workspace override matching,
custom hoisted module directories and runtime/engine checks change consumption
without changing accepted setting shapes. pnpr services require advertised
protocol capabilities and a server newer than 0.1.0-alpha.19. Global setup,
self-update, auth and bundled node-gyp changes need no migration rule.

The native registry fixture includes 11.28.11 as the preceding control and
11.28.12 as the first rejecting patch. Migration retention and rejection before
writes cover all three strategies. See the
[release notes](https://github.com/pnpm/pnpm/releases/tag/v11.28.12),
[placeholder handling](https://github.com/pnpm/pnpm/blob/v11.28.12/pnpm11/config/reader/src/replaceEnvInSettings.ts)
and [project npmrc reader](https://github.com/pnpm/pnpm/blob/v11.28.12/pnpm11/config/reader/src/loadNpmrcFiles.ts).

## 11.28.13

Compared exact tags **11.28.12 → 11.28.13**. The workspace field types are
unchanged. The config reader now derives `rawLockfileDir` from `lockfileDir` for
maintenance commands and explicitly refuses a project-supplied
`rawLockfileDir`. The migrator reports it as project-refused, preserves it in
legacy sources, and rejects existing workspace YAML containing it before
writes. The public `lockfileDir` keeps its existing migration behavior.

When overlapping `overrides` selectors both match, pnpm now chooses the narrower
range regardless of declaration order. The migrator preserves both selectors
and their order. Native fixtures exercise both source orders on 11.28.12 and
11.28.13. Node runtime selection now follows the dependency groups being
installed. Registry changes cause policy checks to be refreshed, and `dlx`
includes active policies in its cache identity. These are consumption changes
for existing settings. `globalPackagesConfig` in global YAML is identified as
a newer v12 setting.
