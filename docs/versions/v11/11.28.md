# pnpm 11.28

Compared with pnpm 11.27.x. Patch changes within 11.28.x are listed at their exact release boundaries.

## 11.28.0

`forceIgnoresPlatform` becomes available; only explicit values move. pnpm v11
and v12 have different defaults, which the migrator does not materialize.
Dynamic `userAgent` values containing environment placeholders remain in their
sources because pnpm ignores them in project configuration.

## 11.28.1–11.28.6

From 11.28.1, invalid `patchedDependencies` maps and non-array `packages` values
are retained with diagnostics. Incompatible existing workspaces fail validation
before writes.

From 11.28.3, non-null `allowBuilds` values must be maps of booleans or strings.
From 11.28.4, non-null `allowUnusedPatches` must be boolean, and non-null
`ignoredOptionalDependencies` / `requiredScripts` must be string arrays.
From 11.28.5, `httpProxy` and `httpsProxy` must be strings, including when empty;
null is incompatible in 11.28.5. From 11.28.6, null is accepted again and leaves
the proxy unset. Invalid values remain in their sources with diagnostics.

## 11.28.7

`maxTarballUnpackedSize` accepts a nonnegative safe integer in bytes or null.
Numeric `.npmrc` values become YAML numbers. The migrator does not add pnpm's
4 GiB default. `autoInstallPeersFromHighestMatch` accepts boolean or null;
`externalDependencies` accepts a string array or null.

## 11.28.9

From pnpm 11.28.9, v11 registry declarations also accept `serverType: pnpr`.
Earlier or unconfirmed v11 targets retain the complete registry map. The setting
does not enable v12-only registry fields such as `networkConcurrency` or `ecosystem`.

## Other recorded patches

11.28.2 and 11.28.8 add no field migration rule in the corresponding audits.
11.28.10 and 11.28.11 leave the ordinary workspace schema unchanged. The latter
normalizes default-registry prefix lockfile keys; source settings need no rewrite.
