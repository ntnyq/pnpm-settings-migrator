# pnpm 12.0

Compared with v11: this file establishes the v12 major baseline and records
workspace-reader limitations found by the existing audits. It is not an
exhaustive reconstruction of every 12.0 setting.

## Major transition

The v12 workspace reader rejects unknown settings when the project pin matches.
`globalShims` is a v12 field at this baseline; it moves to trusted global scope
at [12.8.2](12.8.md).

`packageConfigs` is unavailable in 12.0–12.3 and returns at [12.4](12.4.md).
The v11 migration conversions continue where the v12 schema accepts their output;
see the [v11 transition](../v11/11.0.md).

## Workspace fields not consumed

pnpm v12 reads `filter` and `filterProd` from CLI arguments or `updateConfig`
hooks, not workspace YAML. These settings remain in their source with
diagnostics for v12 targets; existing YAML containing them blocks migration.
The 12.11.2 hook fix does not add workspace support.

Other legacy fields ignored by the audited v12 workspace reader also stay in their
sources with diagnostics. These include `production`, `dev`, `recursive`,
`lockfileOnly`, `force`, `depth`, `saveDev`, `fetchingConcurrency`,
`extraBinPaths`, `extraEnv`, and `workspacePackagePatterns`.
Existing YAML containing ignored fields blocks migration before writes.
For example, `production=true` cannot be moved into v12 YAML; use
`pnpm install --prod` to select production dependencies.

Other fields become consumable later: `loglevel` / `progress` at [12.6](12.6.md),
`reporter` at [12.7](12.7.md), `failIfNoMatch` at [12.10](12.10.md),
`provenance` at [12.11](12.11.md), and `requiredScripts` with the TLS/runtime/tag
fields at [12.16](12.16.md). These are workspace-reading boundaries, not claims
that the names were first introduced in those releases.

Linux `packageImportMethod: auto` becomes hardlink-first. The stricter
`engineStrict` behavior can reject dependencies inside optional subtrees. The
migrator preserves explicit values and writes no defaults for either change.
The removed `pnpm install --resolution-only` command is outside settings migration;
replace it with `pnpm peers check` in scripts when upgrading.
