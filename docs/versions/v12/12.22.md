# pnpm 12.22

Compared exact tags **12.21.0 → 12.22.0**, including the full configuration
crate, the v13 lockfile implementation, and the release notes. Existing
project workspace field names, scalar settings, nested shapes and defaults
continue to apply.

## Global package scope

From **12.22.0**, `globalPackagesConfig` in the machine's `config.yaml` applies
to commands that act on global packages. It takes precedence over ordinary
global configuration, with environment settings and CLI flags taking precedence
over it. The section accepts workspace-shaped settings. Global package installs
disregard its `catalog`, `catalogs`, `overrides`, `packageExtensions`, and
`patchedDependencies` keys. Global build approvals now save decisions under
`globalPackagesConfig.permissions`. The workspace file belonging to the global
packages directory remains a deprecated source of existing build decisions.

The migrator retains `globalPackagesConfig` in legacy project sources with a
project-refused diagnostic and rejects it in an existing project workspace
before writes. The native fixture verifies that project YAML cannot supply it
and that only global installation uses its store override on 12.22.0, with
12.21.0 as the preceding control.

The top-level global file now warns about and skips workspace-only settings,
including `lockfileDir`, `workspaceConcurrency`, and `peersSuffixMaxLength`.
`blockExoticSubdeps` and `excludeLinksFromLockfile` now take effect globally.
Global `config set` accepts `pmOnFail`, `runtimeOnFail`, and structured `tools`.
Both socket spellings were already accepted in project YAML. This release
also recognizes `max-sockets` in global CLI routing and reports the resolved
`maxSockets` and `maxsockets` aliases. Existing migrated `maxSockets` remains
valid.

## Consumption changes

- `lockfile.format: v13` still selects the experimental JSON lockfile. Local
  directory dependency entries now carry declared specifiers beside resolved
  versions, with `injected: true` inline for injected packages. pnpm rewrites
  the lockfile on a regular install. The fixture checks old and new layouts and
  frozen installs before and after a manifest specifier changes.
- Registry URLs containing environment placeholders now receive the same
  native protection in flow-style YAML. The migrator already checks the parsed
  setting values. Python registry patterns retain their accepted shapes with
  improved diagnostics for invalid patterns.
- Override range precedence, `catalog:` resolution for local `file:`
  dependencies, local dependency skills, runtime selection, pipeline inputs
  and registry policy re-verification improve native consumption of existing
  settings. The migrator keeps explicit settings without materializing defaults.
