# pnpm 12.21

Compared exact tags **12.20.0 → 12.21.0**, including release notes, the full
configuration crate diff and the relocated resolver configuration types. No
added, removed, renamed or deprecated workspace fields, nested shapes or enum
values were found. No new migration capability is needed.

## Consumption changes

From **12.21.0**, `lockfileDir` pointing at the default lockfile directory keeps
the same layout as an unset value. Workspace-relative `modulesDir` and
`virtualStoreDir` settings retain their anchors, including when commands run
inside a workspace package. When `sharedWorkspaceLockfile: false`, an explicit
`lockfileDir` still pins the workspace to one shared lockfile; the migrator must
preserve it rather than remove it as a redundant default.

The migrator continues moving explicit `lockfile-dir=.` to `lockfileDir: .`
without inserting, normalizing away or rewriting user defaults. The real-release
fixture checks source cleanup, native configuration reading, installed package
paths and unchanged frozen installs on 12.20.0 and 12.21.0, with both values of
`sharedWorkspaceLockfile`. This is a consumption check, not a claim to reproduce
every upstream path regression.

`RegistryDeclaration`, registry ecosystem/prefix types, `ResolutionMode` and
`packageExtensions` types move into the resolver crate with the same accepted
shapes. Existing schema validation remains applicable. pnpr fallback and response
limits, peer resolution, v13 lockfile parsing/writing, hoisted/frozen-store
linking, deploy, Python workspace detection and offline store preparation do not
require changes to migrated configuration values. No upstream defaults are
materialized by this update.
